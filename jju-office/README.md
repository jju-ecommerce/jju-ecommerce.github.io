# 쭈대표 AI 오피스

쭈대표님 전용 모바일·PC 통합 관제 웹앱(PWA)입니다. 본폰 1대와 서브폰 3대에서 움직이는 비서 4인방(주드 총괄이사 · 하루 팀장 · 다온 과장 · 로이 대리)을 한 화면에서 지휘합니다.

- 주소: https://jju-ecommerce.github.io/jju-office/
- 모바일 미리보기(PC에서 폰 화면 확인): https://jju-ecommerce.github.io/jju-office/preview.html
- 설치: 안드로이드 크롬 `⋮ → 앱 설치` / 아이폰 사파리 `공유 → 홈 화면에 추가`

## 동작 방식

1. **로컬 모드(기본)** — 서버 없이 바로 동작합니다. 회의실 메시지·할 일은 그 기기 브라우저(localStorage)에 저장됩니다.
2. **AI 서버 연결(Supabase)** — 우측 상단 `AI 서버` 배지를 눌러 Project URL 과 anon key 를 넣으면 `office_messages` · `office_tasks` 테이블과 동기화됩니다. `🔋 AI 한도` 탭은 `office_ai_quotas` 테이블과 따로 동기화하며, 그 테이블이 없어도 앱의 다른 화면은 영향받지 않습니다. 회의실의 **안 읽은 인원수**는 `office_reads` 테이블을 쓰고, 이 테이블이 없어도 나머지 화면·대화는 그대로 동작합니다(v41). **6초 주기**로 확인하되, 회의실 글은 **처음 한 번만 최신 200건**을 받고 그 뒤로는 **마지막으로 받은 글 이후만**(`created_at=gt.`) 받아 옵니다(v39 — 전송량 절감). 여러 기기에서 같은 회의실·할 일을 봅니다. 할 일은 `📋 할 일` 탭을 보고 있을 때 매 주기, 다른 화면에서는 5주기(약 30초)에 한 번, AI 한도는 한도 화면에서 3주기(약 18초)에 한 번 맞춥니다. **폰이 잠기거나 앱을 뒤로 보내면 폴링을 멈추고**, 돌아오면 즉시 한 번 동기화한 뒤 다시 켭니다.

### ✋ 터치모니터 확대 + 세 칸 바닥선 맞춤 (v46 · styles v37 · app v46 · sw v40)

- **대표님 지시(2026-11-27)** — "사이드를 대화창 길이까지 늘려서 화면이 꽉차보이게, 터치모니터라 터치가 용이하게 아이콘을 키워줘".
- **세 칸 바닥선이 한 줄** — 왼쪽 레일·가운데 단(4인방 현재 위치)·오른쪽 대화창 카드의 **아래 끝이 같은 선**에서 끝납니다. PC 1024px 이상에서 레일 아래 여백을 대화창 카드와 같은 16px로 맞추고, `.pc-side`·`.pc-side-card` 가 남는 높이를 나눠 가지며 카드 안 목록(4인방·할 일·AI 한도)이 **줄 간격을 고르게 벌려** 채웁니다(빈 공간을 만들지 않음). 가운데 단의 `4인방 현재 위치` 카드도 남는 높이를 받아 4개 상태 카드가 함께 늘어납니다.
  - 실측(로컬 실행 하네스): `1440×900` 884 = 884 · `1536×960` 944 = 944 · `1366×768` 752 = 752 · `1280×800` 784 = 784 · `1280×680` 664 = 664 — **레일·대화창·4인방 카드 바닥선 완전 일치, 세로 스크롤 0px**(`scrollHeight === clientHeight`).
- **터치 크기 확대**
  - 왼쪽 메뉴 10칸: 아이콘 **21 → 26px**(높이 820px 이하 **24px**), 한 칸 최소 높이 **48px**(1280×680 48px · 1366×768 57px · 1440×900 67px) — 아이콘 위·이름 아래 구성은 그대로.
  - 카드 우상단 버튼(`오피스 맵 열기 →` · `할 일 전체 보기 →` · `AI 한도 자세히 →`): 글씨 13.5→**14px**, 높이 28~32px, **`::after` 로 사방 8px 히트 영역 확장**(보이는 크기는 그대로, 손가락으로 누르기 쉽게). 절대배치를 풀어 카드 그리드 1행 2열로 옮겨 버튼이 커져도 목록 첫 줄을 덮지 않습니다.
  - 대회의실/지휘실/라운지 방 탭: 높이 **48px**(11px 6px 패딩 · 15px 글씨).
  - 입력창 `+` 44→**50px**, `🖼️`·`📷` 46→**52px**(아이콘 23→**26px**), `보내기` 16→**17.5px**(높이 52px) — **입력창 한 줄 유지**(1280×800 입력 폭 145px, 넘침 0).

### 📐 13.3형 짧은 화면(1280×680 · 1366×768) 세로 무스크롤 — 한 화면에 다 (v45 · styles v36 · app v45 · sw v39)

- v44 에서 2단 배치·사이드바 확대는 1440×900 에서 잘 맞았지만, 세로가 짧은 13.3형에서는 ① 왼쪽 레일이 **86px 스크롤**되고 ② 왼쪽 단(오피스 맵 + 4인방 현재 위치)이 **118px 모자라** 4인방 카드 아래가 잘렸습니다(1366×768 은 48px 모자람). v45 는 이 두 곳을 여백만 조여 맞춥니다.

- 15MB가 넘는 원본·사진이 아닌 파일은 안내만 하고 붙이지 않습니다.

**서버 준비(사진을 4기기로 함께 보려면)** — `supabase-office-schema.sql`의 두 블록이면 끝입니다.

1. `alter table office_messages add column if not exists image_url text;` — 사진 주소 칸
2. Storage 공개 버킷 `office-attachments` + anon 정책(insert/select/update)

준비 전에도 앱은 고장 나지 않습니다:

| 상태 | 동작 |
| --- | --- |
| 컬럼 없음(42703) | 사진은 이 기기 말풍선에만 남고, **글은 그대로 전송**됩니다. `image_url` 없이 같은 id로 다시 넣어 중복 행이 없습니다. 미리보기에 `DB 준비 전 · 이 기기에만 표시` |
| 버킷 없음(404)/정책 거부(403) | 업로드를 건너뛰고 **글만 전송**, 사진은 기기에 남습니다. 안내: `스키마 SQL의 Storage 블록을 실행해 주세요` |
| 서버 미연결 | 기기에만 저장(사진 포함). 연결하면 그 뒤 사진부터 4기기 공유 |
| 확인 불가(네트워크) | 그대로 시도하고, 실패하면 글만 전송 |

사진 주소를 직접 넣고 싶을 때:

```bash
curl -X POST "$SUPABASE_URL/rest/v1/office_messages" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer $ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"room":"grand","author":"jju1","author_name":"하루 팀장","body":"신상품 샘플 사진입니다","image_url":"https://xfcmfytdfkwuqgsnqogo.supabase.co/storage/v1/object/public/office-attachments/office/2026-11-27/sample.jpg"}'
```

### 원터치 연결 (주소 한 줄)

각 기기에서 `AI 서버` 창에 키를 직접 넣지 않아도, 아래처럼 주소 끝에 `#sb_url=...&sb_key=...` 를 붙여 한 번 열면 설정이 그 기기 브라우저에 저장되고 바로 연결됩니다. 연결되면 앱이 주소창의 해시를 스스로 지워 깔끔하게 남깁니다.

```text
https://jju-ecommerce.github.io/jju-office/#sb_url=<Project URL>&sb_key=<anon key>
```

이 해시 주소는 비밀번호와 같습니다. 단톡방·SNS에 그대로 올리지 말고, 기기마다 한 번씩만 열어 주세요. 이 저장소(공개)에는 키가 들어 있지 않습니다.

### Supabase 준비

1. Supabase 프로젝트를 만들고 **SQL Editor** 에서 [`supabase-office-schema.sql`](supabase-office-schema.sql) 을 실행합니다.
2. **Project Settings → API** 의 `Project URL` 과 `anon public` 키를 앱의 `AI 서버` 창에 넣고 **저장**을 누릅니다.
3. `연결 테스트` 로 테이블까지 붙었는지 확인할 수 있습니다.

> anon key 는 앱을 쓰는 기기의 브라우저에만 저장되며 이 저장소에는 들어 있지 않습니다. 스키마는 개인 오피스 기준으로 anon 역할에 읽기·쓰기를 열어 두었으니 키를 외부에 공유하지 마세요.

### 메시지 author 값

`boss`(대표님) · `director`(주드 총괄이사, 본폰) · `jju1`(하루 팀장, 1번 폰) · `jju2`(다온 과장, 2번 폰) · `jju3`(로이 대리, 3번 폰). 비서 쪽에서 아래처럼 넣으면 회의실에 바로 뜹니다.

```bash
curl -X POST "$SUPABASE_URL/rest/v1/office_messages" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer $ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"room":"grand","author":"jju1","author_name":"하루 팀장","body":"1번 12:31 발행 완료했습니다."}'
```

`room` 은 `grand`(대회의실) · `command`(지휘실) · `lounge`(라운지) 중 하나입니다.

### 회의실 사진(`office_messages.image_url` · v38)

`office_messages` 에 `image_url`(text, 선택)이 추가됩니다. 값은 Storage 공개 버킷 `office-attachments` 의 주소(`.../storage/v1/object/public/office-attachments/office/YYYY-MM-DD/<파일>.jpg`)이고, 사진은 앱이 올린 뒤 그 주소만 저장합니다. 글 없이 사진만 보낸 경우 `body` 는 `📷 사진` 으로 들어가 예전 버전(v37 이하) 앱에서도 빈 말풍선이 되지 않습니다. 사진 경로는 `office/날짜/` 아래에 쌓이므로 Storage 용량을 비우고 싶을 때 이 폴더 단위로 지우면 됩니다.

### 할 일(`office_tasks`) 컬럼

`id`(uuid) · `title`(text) · `owner`(text — `boss`·`director`·`jju1`·`jju2`·`jju3`) · `done`(boolean) · `due_date`(date, 선택) · `created_at` · `updated_at`

비서 쪽에서 할 일을 올리거나 완료 처리할 때:

```bash
curl -X POST "$SUPABASE_URL/rest/v1/office_tasks" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer $ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"title":"에이블리 페이백 결정","owner":"boss","done":false}'

curl -X PATCH "$SUPABASE_URL/rest/v1/office_tasks?id=eq.<id>" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer $ANON_KEY" \
  -H "Content-Type: application/json" -d '{"done":true}'
```

날짜 약속은 `due_date` 에 `YYYY-MM-DD` 를 넣습니다(비우면 날짜 없는 할 일). 앱에서도 같은 방식으로 저장되고, 화면에서는 `오늘`·`내일`·`11/28 (토)`·`지남` 배지로 보입니다.

```bash
curl -X POST "$SUPABASE_URL/rest/v1/office_tasks" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer $ANON_KEY" \
  -H "Content-Type: application/json" \
  -d '{"title":"달리바 상세페이지 검수 약속","owner":"boss","done":false,"due_date":"2026-11-28"}'

curl -X PATCH "$SUPABASE_URL/rest/v1/office_tasks?id=eq.<id>" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer $ANON_KEY" \
  -H "Content-Type: application/json" -d '{"due_date":null}'
```

### 자료실(`office_deliverables`) 컬럼

`id`(uuid) · `title`(text) · `description`(text) · `category`(text — `ebook`·`video`·`image`·`doc`·`util`) · `kind`(text — `pdf`·`md`·`csv`·`xlsx`·`image`·`video`·`web`·`sheet`·`doc`·`app`·`sql`) · `url`(text, 바깥 링크) · `file_path`(text, 이 저장소 안 경로) · `tags`(text[] 또는 쉼표 문자열) · `size_label`(text) · `locked`(boolean) · `created_at` · `updated_at`

### AI 한도(`office_ai_quotas`) 컬럼

`id`(text PK — `director`·`jju1`·`jju2`·`jju3`·**`chatgpt`·`codex`(v39)**) · `plan`(text, 플랜명) · `status`(text — `free`·`watch`·`near`·`out`) · `percent`(integer 0~100) · `reset_note`(text, 다음 리셋 예정) · `memo`(text) · `updated_by`(text) · `updated_at`(timestamptz)

`id` 가 `text` 라 ChatGPT·Codex 를 **스키마 변경 없이** 같은 표에 넣습니다(v39). 앱은 `on_conflict=id` upsert로 한 줄씩 올리고, 조회는 `updated_at` 최신순 50건입니다. 테이블이 없거나(404) 응답이 없으면 조용히 기기 저장으로 돌아가고 화면은 그대로 동작합니다.

```bash
curl -X POST "$SUPABASE_URL/rest/v1/office_ai_quotas?on_conflict=id" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer $ANON_KEY" \
  -H "Content-Type: application/json" -H "Prefer: resolution=merge-duplicates" \
  -d '{"id":"jju1","plan":"Free plan","status":"watch","percent":55,"reset_note":"매일 새벽 4시 전후 초기화","memo":"원고 2편 대기"}'
```

### 읽음 현황(`office_reads`) 컬럼 (v41)

`room`(text — `grand`·`command`·`lounge`·`dm:jju1`) · `member`(text — `boss`·`director`·`jju1`·`jju2`·`jju3`) · `last_read_at`(timestamptz) · `updated_at`(timestamptz, 트리거로 자동 갱신) — 기본키 `(room, member)`.

앱은 `on_conflict=room,member` upsert로 한 줄만 올리고, 조회는 `room=eq.<방>&select=member,last_read_at` 입니다. 테이블이 없으면(404) 배지만 안 뜨고 대화·할 일·나머지 화면은 그대로 동작합니다.

```bash
curl -X POST "$SUPABASE_URL/rest/v1/office_reads?on_conflict=room,member" \
  -H "apikey: $ANON_KEY" -H "Authorization: Bearer $ANON_KEY" \
  -H "Content-Type: application/json" -H "Prefer: resolution=merge-duplicates,return=minimal" \
  -d '{"room":"grand","member":"jju2","last_read_at":"2026-11-27T04:30:00.000Z"}'
```

## 보안

이 저장소는 공개 저장소입니다. 대표님의 전화번호·이메일·비밀번호·API 키 같은 개인 정보는 넣지 않았습니다. 서버 접속 정보는 각 기기의 브라우저에만 저장됩니다. 블로그 탭의 고객센터 번호(1566-0902)는 도매에빠지다가 공개한 사업자 대표번호이고, 디렉토리 연락처는 각 디렉토리가 공개한 입점 문의 메일입니다.

자료실 탭에는 대표님이 지시한 드라이브·문서·시트 링크(ID)가 들어 있습니다. 확인 시점(2026-11-27)에 유료 전자책·시트·문서·달리바 로고는 익명 접속에서 401(로그인 필요)로 막혀 있었고, 무료 지침서 웹·PDF·슬라이드만 공개 상태였습니다. 앱은 이 항목에 `🔒 공유 제한` 표시를 붙이고 대표님 Google 계정 로그인 상태에서 새 탭으로 엽니다. 이 링크들 중 하나라도 나중에 ‘링크가 있는 모든 사용자’로 바꾸면 공개 페이지에서 누구나 열 수 있게 되니, 공유 범위를 바꿀 때는 이 점을 확인해 주세요.
